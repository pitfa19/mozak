## What changed

- **One path helper.** `packages/core/src/paths.ts` has `realOrSelf` and `isWithin`. They replace four identical realpath-or-self copies (`settings.ts`, `plans-index.ts`, `locators.ts`, `local-sync.ts`), the plugin's own `realOrSelf` (now re-exported from core), and two identical "inside" checks (`local-sync.ts`, `usage.ts`). `usage.ts` keeps its `realish` as `resolve(realOrSelf(p))`, which is the same result.
- **Folding.** `noteKey` uses `foldKey` instead of repeating it. A test checks that the eval harness copy in `eval/lib/fold.mjs` folds exactly like `fold.ts`.
- **Error messages.** A scan of `new DomainError(...)` calls found 154 sites with 70 codes. Eleven common codes had messages that did not say what to do next. They now end with the next step. Codes and exit codes are unchanged. `error-messages.test.ts` triggers each one.

- **Types.** `tsconfig.base.json` now sets `noUnusedLocals`, `noUnusedParameters`, `noImplicitReturns`, `noFallthroughCasesInSwitch` and `noImplicitOverride`. That needed four removals of unused code (`assertFinite` in `review.ts`, which nothing called, one unused import, one unused helper in the MCP server, one unused type import) and six `override` keywords in the plugin.
- **Scripts.** `npm run typecheck` (`tsc -b`), `npm run lint` (typecheck plus the link check) and `npm run loc`. There is no other linter, on purpose.
- **CI.** `.github/workflows/ci.yml` already runs build, tests and the installer suite on pull requests and pushes to `main`, on Ubuntu and macOS, with Node 24.11.0 and 26, read-only permissions and no secrets. It does not run on `hermes/**` pushes. It now also runs `npm run lint` as its own step, so a typecheck or link failure is named in the job. The owner applied this change on 2026-10-21, because the token used for `hermes/*` branches is not allowed to push workflow files.

## What was left, and why

- **Test scratch helpers.** About 25 test files define their own `scratch` folder. They differ on purpose: some require `TMPDIR`, some fall back to `tmpdir()`, some resolve symlinks. Merging them is not a pure refactor.
- **`locators.ts` `inside`.** It compares path prefixes, not `relative()`. The two give different answers for unnormalized paths, so it was not merged into `isWithin`.
- **`eval/lib/fold.mjs`.** The eval harness runs without a build, so it keeps its own copy. The new parity test guards it.
- **Stricter flags not turned on.** `noUncheckedIndexedAccess` gives 46 errors and `noPropertyAccessFromIndexSignature` gives 820. `exactOptionalPropertyTypes` gives one error, but it changes what optional fields mean, so it should be a separate decision.
- **`SPEC.md`.** It still describes format 1. `docs/README.md` already lists it as a superseded historical record.
- **`docs/demo.gif`.** Nothing links to it. It looks like the old format-1 demo. Removing a binary is left to the owner.
- **Package metadata.** No `package.json` has a `license` field. The repo `LICENSE` is MIT. Adding the field also changes `package-lock.json`, so it is left for a release commit.
- **`@types/node` 22** while `engines` asks for Node 24.11 or newer. Upgrading types is a dev change for a separate commit.
- **`release.yml`** uses `actions/checkout@v4` and `actions/setup-node@v4` by tag, not pinned to a commit like `ci.yml`, and it needs `GITHUB_TOKEN` to publish. It was not changed.

## Open risks

- The removed exports were part of `@mozak/core`'s `index.ts`. No package in this repo or open `hermes/*` branch uses them. A merge check of `hermes/tend` onto this branch is clean, and it compiles with the new flags. Any outside code that imported them would break.
- The new compiler flags apply to branches merged later. Unused locals or a missing `override` there now fail the build.
- The audit ran on macOS with Node 26.10.0 only. Node 24 and Linux were not run locally, and the proposed CI workflow was not run, because it is not in `.github/workflows/` yet and this machine does not trigger GitHub Actions.
